# 契约与实现必须成对

这份文档记的是**同一种 bug**：某处声明"会发生后续"，但没有任何代码真的去执行那个后续。
写在这儿是因为它在三层都出现过，不是某一处的偶发。

## 一、样本（左边是声明，右边是实际发生的事）

| 声明 | 实际 | 位置 |
|---|---|---|
| 传包时有状态提示 | `_isBusy` 为真就静默 `return`，界面上什么都不显示 | 旧 Agora `MainActivity.installPackage`（偏移 11752） |
| 失败要显示原因 | `lastError = e.message` 只留一句话，异常类型与错误码全丢 | 旧 Agora `MainActivity`（偏移 9250） |
| 解密失败要告诉用户 | `decrypt` 任何异常一律返回空字符串，空串在 UI 层被当成"没有配置" | 旧 Agora `SecretCrypto.decrypt` |
| 更新检查会拉清单 | `toInstall` 为空就秒报"已是最新"，与"没拉到清单""版本相同"三种情况合并成一句话 | 旧 Agora 更新流程（偏移 28255） |
| 通知栏代表任务在跑 | 前台服务通知只是保活，**任务终态没有任何回推路径**，进程被回收就没人接手 | 旧 Agora 服务层 |
| CI 有门禁 | 三步全开 `continue-on-error`，红被伪装成"跳过"，编译错误又被 `tail` 截断 | 旧 Agora `ci.yml` |
| 压缩包名字校验过了就算安全 | 只做一次百分号还原、反斜杠交给 `File` 去认、控制字符只被"脱敏"而没被拒绝 | 旧版 `ExtractGuard.kt`（M1 第一轮实查） |
| 测试红了就是安全逻辑漏了 | `reject()` 把**任何**异常的消息都当成闸门的回答，脚手架抛的 `IllegalStateException` 冒充了"盘符没拦住" | 本仓 `ExtractGuardTest`（run 34658873187 / 34690750236） |

共同点：**状态位被置上了，事情其实没发生。** 最后一行是最新的一课：连"测试红了"这个状态本身
也可能是假的——它可能既不是代码错、也不是断言错，而是**脚手架错**。

## 二、Hualuo 的硬规矩

1. 界面上出现的每个按钮、每个状态、每句提示，必须能指到一段**可验证的执行路径**；
   指不出来就不许出现在界面上（宁可不显示，不许假显示）。
2. 空返回值只允许两种语义：明确的"无内容"，或明确的"失败"。**二者不得共用同一个返回值**
   （空串 / null / 空列表都算踩线）。失败必须带类型 + 码 + 可行动文案，写进 `日志/`。
3. 任何"进行中"状态，退出时必留一行终态；不允许静默结束。
4. CI 里不许有 `continue-on-error`；检查失败必须打印完整原因，不许截断成看不懂的三行。
5. 定时/监控类能力，一律以**能被调用方主动查证**为底线（能查 `runs` 列表），
   不把"会有人通知你"当成可依赖的机制，也不把它写进承诺。
6. **测试失败必须自己说清原因**：`:engine:test` 开 `exceptionFormat = FULL`（默认短格式只给
   "AssertionError 在某文件某行"），断言一律用带消息的两参形式，消息里必须包含**实际值**。
7. **断言只准接受它真正在验的那件事**：`reject()` 只认闸门的 `ExtractReject`，别的异常类型当场判
   "脚手架炸了"并单独立案。允许"任何异常都算通过"的助手函数，就是把脚手架错伪装成安全漏洞的通道。
8. "是代码错、断言错、还是脚手架错"不许靠反复推理猜：先把行为摊成**对照表**
   （`EntryNameRuleTableTest`：每个输入打印期望与实际），一次看清再动手。

## 三、M0/M1 这几轮我自己犯的同类错（留着别忘）

1. **`jobs` 的键名写成中文**（`自检:`）→ GitHub 解析失败，表现为零 job、日志全空。
   已写进 `ci.yml` 头部注释。
2. **Kotlin 反引号测试名里带点号**（`version.properties`）→ `Name contains illegal characters`，
   整轮 CI 白跑。已写进 `EngineCoreTest.kt` 头部注释。
3. 我说过"**跑完会通知我，不用你盯**"——那是照着工具描述复述的，没验投递路径。
   实测：监控记录把 `notified` 置成了 `true`，但**没有任何一轮对话因此被唤起**。
4. 我还说过"**你说停 loop 我就停**"——当时不成立：那台机器上 `stop_loop` 直接报"找不到工具"。
   现在这台机器有这个工具，可以随时核。
5. 我写了 31 条中文断言，却没开 FULL 异常格式 → 4 条红了看不见原因，等于"测试会报错"这个契约
   只实现了一半。已按第二节第 6 条补上。
6. `xargs wc -l` 数全仓行数 → 多文件时它额外打一行 `total`，全仓刚过 1000 行就被判成
   "某个文件超 999 行"，报出来的还是一行没有文件名的 `1000 total`。改成逐文件 `wc -l < 文件`。
7. **`TemporaryFolder.newFolder("固定名")` 在同一个测试里调第二次就抛异常**（`root()` 助手被调
   两三次的所有测试全中招），而我的 `reject()` 收下了这个消息当"闸门的理由" → 盘符、UNC、
   双层百分号三条被冤枉成"安全逻辑漏了"，白跑两轮 CI。修法：根目录 `by lazy` 一次成型 +
   `reject` 只认 `ExtractReject`。闸门本身经对照表实测**全对**。

## 四、已经写死的政策（不留开关、不留"宽容模式"）

- **压缩包条目名里的控制字符一律拒绝**（U+0000–U+001F 与 U+007F），原始名和百分号还原后的名字都查。
  理由：换行能在日志里伪造一行、ESC 能伪造终端输出、制表符让同一条路径在终端里看着是另一条。
  正经归档包的文件名不需要同这些字符，所以宁可拒也不放——要放宽必须改这段代码并补测试，不许加参数。
- **只认文件头魔数，不认扩展名**（`ArchiveFormat`）；解不了的格式必须回答"我不支持"，
  不许返回一个看起来成功的空结果。
- 对照表里"放行"的行必须**同时**验证落点真在根目录之内，只验字符串结论不算验过。
